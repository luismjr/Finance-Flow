# Finance Flow

<img width="1470" height="798" alt="Screenshot 2026-05-14 at 3 05 30 PM" src="https://github.com/user-attachments/assets/6166272f-4c6b-4269-8be3-71f2816756e6" />

An end-to-end ELT data pipeline that ingests daily stock prices and macroeconomic indicators from public financial APIs, transforms them with dbt, and surfaces actionable market insights in a Django dashboard. Runs fully locally on SQLite/Postgres with one command — cloud storage (GCS) and warehouse (BigQuery) integrations are wired into the Airflow DAGs and perform real uploads/loads once `GCS_BUCKET_NAME`, `BIGQUERY_PROJECT_ID`, and `GOOGLE_APPLICATION_CREDENTIALS` are set (see `.env.example`); with no credentials configured, the same tasks log what they would have done so the project still runs with zero cloud setup.

**At a glance** (generated by `make dev`'s demo data seeder, so the numbers are reproducible — not pulled from a live deployment):
- **50 S&P 500 stocks** tracked across 5 sectors
- **26,150+ OHLCV records** spanning 2 years of trading history
- **12 FRED macroeconomic series** (Fed Funds Rate, CPI, Unemployment, GDP, VIX, etc.)
- **47 dbt tests** enforced across 4 models — 100% passing
- **~99% simulated pipeline success rate** across 270 seeded DAG runs (90-day history)
- **< 15 min end-to-end latency** from API ingestion to mart layer

## Quickstart (local, no cloud needed)

```bash
# Clone and set up
git clone https://github.com/luismjr/Finance-Flow.git
cd Finance-Flow
python3 -m venv .venv && source .venv/bin/activate
pip install -r app/requirements.txt

# Run with pre-seeded demo data (no API keys needed)
make dev
# → http://localhost:8000
```

To ingest **live data** from the real APIs:

```bash
cp .env.example .env
# Add your free ALPHA_VANTAGE_API_KEY and FRED_API_KEY to .env

make ingest-stocks   # pulls 50 tickers via yfinance
make ingest-macro    # pulls 12 FRED series
make dbt-run         # rebuilds mart tables
make dbt-test        # runs all 47 quality tests
```

## Full stack with Docker (includes Airflow)

## Cloud Setup (optional — real GCS + BigQuery + Looker Studio)

By default everything runs locally with zero cloud setup. To make the DAGs perform real
cloud writes and to build a Looker Studio dashboard on top of real data:

1. Create a GCP project (free tier is enough at this data volume — 26k+ rows is well
   under BigQuery's 10 GB/1 TB-query monthly free allowance).
2. Enable the **Cloud Storage API** and **BigQuery API** for the project.
3. Create a service account with the **Storage Object Admin**, **BigQuery Data Editor**,
   and **BigQuery Job User** roles, then download its JSON key.
4. Save the key as `airflow/secrets/gcp-credentials.json` (gitignored; already mounted
   into the Airflow containers by `docker-compose.yml` at `/opt/airflow/secrets/`).
5. Create a GCS bucket for raw data.
6. Copy `.env.example` to `.env` and set `GCS_BUCKET_NAME`, `BIGQUERY_PROJECT_ID`, and
   `GOOGLE_APPLICATION_CREDENTIALS=/opt/airflow/secrets/gcp-credentials.json`.
7. `docker compose up -d`, then trigger the `stock_ingestion` and `macro_indicators`
   DAGs from the Airflow UI (`http://localhost:8080`) to do a real load.
8. Point dbt at BigQuery instead of Postgres for the transform layer (see
   `dbt/profiles.yml` target config) and `make dbt-run`.
9. Once real tables exist in BigQuery, go to [lookerstudio.google.com](https://lookerstudio.google.com),
   create a new report, add a data source using the built-in BigQuery connector, select
   the project/dataset/table, and build charts directly on the mart tables
   (`mart_stock_analytics`, `mart_volatility_metrics`, `mart_sector_aggregations`).
   Looker Studio itself is free and needs no billing account.

## Pipeline DAGs

### `stock_ingestion` — Mon–Fri @ 06:00 ET

```
fetch_stock_prices → upload_to_gcs → load_to_bigquery → validate_record_count
```

Fetches OHLCV data for 50 tickers via yfinance. Quality gate fails the DAG if fewer than 40 tickers ingest successfully, blocking downstream dbt transforms from receiving incomplete data. The `upload_to_gcs`/`load_to_bigquery` tasks perform a real GCS upload and BigQuery load job once `GCS_BUCKET_NAME`, `BIGQUERY_PROJECT_ID`, and `GOOGLE_APPLICATION_CREDENTIALS` are set; without those, they log what they would have done so the DAG still completes with zero cloud setup. See `.env.example` for the exact setup steps.

### `macro_indicators` — Monthly @ 08:00 ET

```
fetch_fred_series → upload_to_gcs → load_to_bigquery → validate_series_coverage
```

Pulls 12 FRED economic series. Validates minimum observation count before marking the run successful.
